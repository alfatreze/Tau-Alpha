## 0. Layers
```
 clients (decoder, scanout, engine, CPU bridge, DMA)        <- project code
   |  client port protocol (section 4), identical for every scheduler
 scheduler  (tau_sdram_sched_v : Tau V throughput;  tau_sdram_sched_a : Tau Alpha simple)   <- one per project
   |  command interface (section 3.3): one command per clock, registered permit vectors back, write data pushed with wvalid
 PHY + interlock  tau_sdram_phy   (pins, I/O registers, init, refresh timer and preemption, legality interlock, read capture)   <- shared, frozen per tag
   |  pins
 chip model (sim only): timing, data and drive-window checker, written independently of the PHY
```
The scheduler decides WHICH command and WHEN; the PHY guarantees that **an illegal command never reaches the chip** and that every pin is registered in an I/O cell. The interlock never stalls (3.6): a scheduler bug costs the data of that request and sets a sticky fault, never the unit and never a deadlock.

## 1. Hardware facts
* **Chip:** Alliance `AS4C32M16MSA-6BIN`, 1.8 V mobile SDR, 32M x 16 (64 MB), 4 banks x 8,192 rows x 1,024 columns, 16-bit DQ, two byte masks. Timing: `SDRAM_PART_FACTS.md` (to be diffed against the MSA sheet before the PHY is frozen; every number is a parameter in integer picoseconds).
* **Pins** (`core_top.v`): `dram_a[12:0]`, `dram_ba[1:0]`, `dram_dq[15:0]` (inout), `dram_dqm[1:0]` (`dqm[0]` = DQ[7:0]), `dram_clk`, `dram_cke`, `dram_ras_n`, `dram_cas_n`, `dram_we_n`. **No chip select**: command = {RAS#, CAS#, WE#}. All at 4 mA; `dram_clk` has a 50 ohm series termination.
* **Chip clock:** `dram_clk` is the inverse of the controller clock `clk` (a DDIO output cell, datain_h 0 / datain_l 1), so the chip samples a command half a period after the controller launches it. Baseline 100 MHz, CL2. 133/150 MHz (CL3) is a later PHY variant (`CLK_VARIANT`) with its own chip-clock phase; not a parameter of this one.
* **I/O registers (must):** every output pin is driven by a register that drives only that pin with `FAST_OUTPUT_REGISTER ON`; `dram_dq` has one output-enable register per bit with `FAST_OUTPUT_ENABLE_REGISTER ON`; every DQ input is captured by one register per bit (fanout 1, `FAST_INPUT_REGISTER ON`, or an `altddio_in` for the falling-edge mode). The SDC carries a generated clock for `dram_clk`, output delays from the datasheet (setup/hold **address 1.5/1.0 ns, command and DQM 1.5/1.5 ns, data 1.5/1.0 ns**, the datasheet's "0.5/1.5" for commands being a probable transposition, plus 0.3 ns board margin) and input delays for the read path with **tOH floor 1.8 ns (unloaded)**; every fit reports the slack at slow 85C and fast 0C (`tools/sdram_sta_probe.tcl`; `s0-b905` has the output side).
* **Read timing window (est., 100 MHz, CL2).** Let E be the controller clock edge that accepts a READ. The chip samples it at E+0.5 tCK; word 0 is valid from E+0.5+(CL-1) tCK + tAC to E+0.5+CL tCK + tOH, before the board delay. CL2: about E+2.30..E+2.75 tCK; CL3: E+3.00..E+3.75 tCK. **No rising edge of `clk` falls inside either window** unless the round trip is at least 2.5 ns plus the hold, and an integer pipeline depth cannot centre it; **the falling edge (E+2.5 or E+3.5) fits with about 2 ns each side.** Therefore the capture mode is a parameter `CAP_MODE`: `FALL` (default: DQ captured on the falling edge of `clk` by an `altddio_in` or equivalent, then transferred to the rising domain by one register), or `RISE` (capture on the rising edge after `RD_EXTRA` delay cycles; kept for the phase sweep and for variants with a capture PLL clock). **This applies to the 100 MHz CL2 baseline too, not only to the later variants** (Tau V). The existing `sdram_fb` is reported (by Tau V, not re-verified here) to work on hardware at 100 MHz with rising-edge capture, so the worst-case window above (tAC 8 ns, tOH 1.8 ns, no board delay) is pessimistic for real silicon and `RISE` mode must be able to reproduce that behaviour; the default stays `FALL` for the margin until the chip model and the Pocket sweep show otherwise. The Pocket sweep (7.6) decides; the chip model checks both modes analytically (7.1).
* **`RD_LAT` (exported `localparam`, in cycles):** the number of controller clocks from the cycle that accepts a READ (the cycle in which `cmd` = READ is sampled by the PHY) to the cycle in which word 0 is on `rdata` with `rvalid` = 1. Estimate: `CL + 2 + RD_EXTRA` (the chip model's reference driver measured CL+2 in `FALL` mode with one command register, a falling-edge capture register and one rising transfer register, and CL+1 with rising capture at a typical tAC of 4 ns; the PHY testbench asserts its own architecture's value, not this formula) (the command output register +1, the I/O capture register +1), plus 1 in `FALL` mode if the half-cycle transfer register is needed; **every rule in this contract is written against `RD_LAT`**, never against `CL`. The chip model reports the measured value and the PHY testbench asserts the formula.
* **Mode register:** burst length full page (`111`), sequential, CL 2 or 3 as parameter, write burst programmed (A9 = 0, not single-location write), reserved bits 0: **`MRS BA=00, A=0x027` (CL2) or `0x037` (CL3)**. (The old note "0x227-style" in `SDRAM_PART_FACTS.md` has A9 = 1: wrong for this contract; check what the old controller programs only through the chip-model baseline run, not by reading it.) **Extended mode register: always programmed by this PHY.** Settled from the datasheet text (sibling sheet AS4C32M16MS-6BIN Rev 1.0, Power On and Initialization, p. 7-8): after PRECHARGE the "Mode Register and Extended Mode Register Set Command must be issued", two auto refreshes before or after them, and the power-on mode-register state "may be undefined"; so it is required by the sheet, not optional (the MSA sheet is still to be diffed). `EMRS BA=10, A=0x000` (full drive strength, full array; DS and PASR fields, A[12:11] reserved 0). CL2 needs tCK >= 9 ns (110 MHz max).
* **tRAS(max) = 100 us.** An open row older than `OPEN_ROW_MAX_NS` (default 60,000) is a scheduler duty to close (the PHY reports `row_aged`); the PHY closes nothing behind the scheduler's back except in the preemption of 3.7.

## 2. Timing parameters
All integer picoseconds, converted at elaboration with `$error` checks (no `real`, no `CEIL` that adds a cycle to an exact ratio). At 100 MHz / 133 / 150 MHz: tRCD 18 ns 2/3/3; tRP 18 ns 2/3/3; tRAS 42 ns 5/6/7; tRC 60 ns 6/8/9; **tRFC 97.5 ns 10/13/15**; tWR 15 ns 2/2/3; tRRD 2 clk; tMRD 2 clk; tCCD 1 clk; tCDL 1; tBDL 1; tRDL/tDPL 2 clk; tDQZ (DQM to read data high-Z) 2 clk; tROH = CL clk; **tDAL = tWR + tRP = 4 clk at 100 MHz**. Read: tAC 5 ns (CL3) / 8 ns (CL2), tOH 1.8 ns (floor), tLZ 1 ns, tHZ 5 / 8 ns. tRC also governs ACTIVE to REFRESH.

## 3. PHY interface (`tau_sdram_phy`)
### 3.1 Parameters
`CLK_HZ` (100e6), `CL` (2), `RD_EXTRA` (0..2, default from the sweep), `CAP_MODE` (`FALL`), the section-2 times in ps, `OPEN_ROW_MAX_NS` (60,000), `REFRESH_INTERVAL_PS` (7,800,000), `REFRESH_DEBT_MAX` (8), `INIT_WAIT_CYCLES` (10,000), `PREEMPT_TIMEOUT` (`L_MAX + 8`, L_MAX the largest burst length the scheduler uses, 128 words by default).
### 3.2 Pins
As section 1; `dram_dq` is driven only by the per-bit output-enable registers. CKE is 1 from the first PHY cycle and is **never lowered** afterwards.
### 3.3 Command interface (the scheduler's view; all inputs sampled at the rising edge, all outputs registered)
* **Commands**, one per clock, `cmd[2:0]`: `NOP`, `ACT` (bank, row on `cmd_a`), `RD` (bank, column on `cmd_a[9:0]`), `WR` (bank, column), `PRE` (bank), `PREA` (precharge all, A10), `REF`, `BST`. **There is no MODE_SET and no `cmd_valid`: NOP is the idle command.** A10 on `cmd_a` is 0 for `RD`/`WR` and **a `RD`/`WR` with A10 = 1 is illegal** (auto-precharge acts at the end of a burst, which a full-page burst never reaches). A `BST` with no burst open is replaced by NOP by the PHY (no fault); the chip model flags it if it ever reaches the chip.
* **Permits (registered, exported, valid for the NEXT cycle's offer):** `ok_act[3:0]`, `ok_rd[3:0]`, `ok_wr[3:0]`, `ok_pre[3:0]` (per bank), `ok_ref`, `ok_bst`, `init_done`. The scheduler plans from these; `cmd_ready` does not exist (after `init_done` the PHY always accepts the command in the cycle it is offered).
* **Write data:** `wvalid`, `wdata[15:0]`, `be[1:0]` (`be[0]` = DQ[7:0]). **The scheduler pushes the word in the same cycle as the `WR` command and in every following cycle of the burst; the PHY delays nothing.** While a write burst is open the PHY drives `dqm = wvalid ? ~be : 2'b11`: a cycle with `wvalid` = 0 writes nothing. DQM is `11` at reset, during init and when no burst is open. The PHY alone owns read-side DQM (3.5).
* **Read data:** `rvalid`, `rdata[15:0]`, exactly `RD_LAT` cycles after the accepting cycle, then one word per clock until the burst is ended; **no backpressure**.
* **Status:** `init_done`; `phy_fault` (sticky, cleared only by reset) and `fault_count[15:0]`, `fault_cause[3:0]` (the first cause); `row_aged[3:0]`; `preempt`, `banks_closed` (3.7) and the input `preempt_ack` (3.7); counters `refreshes`, `dq_conflicts` (a simulation assertion; must be 0).
### 3.4 Legality (what the permits and the interlock enforce, per bank and global; times are chip clock edges, READ at r, WRITE at w, n words)
* ACT to RD/WR same bank >= tRCD; PRE to ACT >= tRP; ACT to PRE >= tRAS; ACT to ACT same bank >= tRC; ACT to ACT other bank >= tRRD; REF to any command >= tRFC; ACT to REF >= tRC; REF needs every bank idle (and tRP after a PREA); PREA is legal from any state, subject to tRAS/tDPL/tWR of each open bank; ACT needs the bank idle; a column command needs its bank open (a column command to a closed bank is illegal); tCCD 1.
* **Read:** word k at r+CL+k. `BST`, `RD` (any bank) or `PRE` at r+n ends a read after exactly n words (CL2 and CL3, tROH = CL). Any column command to any bank interrupts the burst in progress; a `PRE` to another bank does not.
* **Write:** latency 0, word k at w+k. `BST` at w+n (tBDL 1); `WR`/`RD` at w+n (tCDL 1); `PRE` at >= w+n+1 with DQM = 11 at w+n (tDPL 2); `ACT` of the same bank >= w+n-1+tDAL. Data present in the `PRE`/`BST` cycle is not written (DQM 11 by the PHY).
* A column wrap past address 1023 is a contract violation (illegal offer). tRAS(max) and per-row tREF are chip-model checks, not interlock functions.
### 3.5 Turnaround (est. at 100 MHz, CL2; the chip model confirms)
* **Read to write:** L = r+CL+n-1 is the last wanted read word. The PHY drives DQM high from the edge L-1 (it owns read-side DQM) and the scheduler offers `WR` no earlier than **L+2** (the chip may drive until L+0.8 tCK because tHZ is 8 ns, the FPGA's enable launches half a clock before the chip edge): one idle bus cycle. The PHY turns the DQ output enable on at the `WR` cycle, never before the last read word has passed. **At CL3 (tHZ 5 ns) the conflict-free `WR` is L+1, but a `WR` cannot end the read itself** (the slot launched at w+CL-1 still drives while word 0 is written): the read must be ended by a `BST` first, so `BST` at L+1 or earlier, `WR` after it. **At CL3 DQM must stay low in the terminating BST/PRE cycle** (DQM at edge e masks slot e+2, so masking starts at L-1 as above, never in the terminating cycle itself).
* **Write to read:** `RD` at w+n (tCDL 1); the PHY turns the output enable off after the last beat.
* **A simulation assertion proves that the FPGA never drives DQ while the chip does** (drive window of the chip: tLZ..tHZ plus the board delay; the FPGA's window from its output-enable register). It gates every install.
### 3.6 Interlock (replaces v0.1's "guard delay", B1)
An offered command that the permits forbid is **replaced by `NOP`**, DQM is forced to `11`, the DQ output enable is turned off, the sticky `phy_fault` is set, `fault_count` incremented and `fault_cause` recorded. The offer is never held (no stall, no combinational path from the scheduler's command to a ready), so there is no deadlock and no extended burst. A correct scheduler never triggers it: **the verification line is "`phy_fault` stays 0 over every test".**
### 3.7 Init, reset, refresh and preemption (B2, B5, M3)
* **Init (also after every reset; a core reload is a reset):** from the first PHY cycle `CKE = 1`, DQM = `11`, DQ OE = 0, NOP for `INIT_WAIT_CYCLES` (10,000 at 100 MHz, counted from CKE high, >= 100 us); `PREA`; tRP; `REF` x2 (tRFC each); `MRS` (section 1); tMRD; `EMRS`; tMRD; `init_done`. The first command after reset is `PREA` even if the previous core left a full-page read running (the wrap is harmless once DQM is high and DQ OE is off, which they are from the first cycle). A real run of the 10,000-cycle wait is part of one test; others may shorten it in simulation.
* **Refresh interval:** at most 64 ms / 8,200 = **7.80 us = 780 cycles at 100 MHz** (a debt of up to 8 then bounds a row at 64 ms + 62.4 us in the worst case; the chip-model checker uses 64 ms + `REFRESH_DEBT_MAX` x interval as its limit and the interval above is the design target). The timer raises `ref_due` and counts `ref_debt[3:0]` (0..`REFRESH_DEBT_MAX`), both exported.
* **The scheduler normally issues `REF`** (one per idle gap, never while an urgent request waits) when `ok_ref` is 1.
* **Preemption (when the debt reaches the maximum and no REF arrived):** the PHY raises `preempt`. The scheduler must reach a burst boundary, end any burst with `BST`/`PRE`, and acknowledge by offering `NOP` for one cycle with `preempt_ack`; or the timeout `PREEMPT_TIMEOUT` expires. The PHY then issues `BST` (DQM `11`), `PREA`, waits tRP, issues `REF`, and pulses `banks_closed` for one cycle: **the scheduler clears its open-row table on that pulse.** The event is counted in `fault_count` (cause "forced refresh") because a correct scheduler never lets it happen, but the data is safe even with no scheduler at all.
* **Aged rows:** `row_aged[b]` is a request to the scheduler; a row that reaches 90 us is closed by the same preemption path (a fault) so a scheduler that forgets cannot violate tRAS(max).
### 3.8 What the PHY must not do
No scheduling, no address mapping, no request queues, no knowledge of ports.

## 4. Client port protocol (identical for every scheduler; M4)
Per port `p`:
* **Request:** `req_valid`, `req_ready` (**registered**), `req_we`, `req_addr[24:0]` (16-bit word address), `req_len[9:0]` (1..512; **0 or 513..1023: the request is rejected, counted in `bad_req` and completes with `done` immediately; never a hang**), `req_tag[7:0]`. The scheduler splits at 1,024-word page boundaries and at its maximum grant length; the client sees **one request**; `w_idx`, `r_last` and `done` are per request, not per grant. A page-crossing split re-ACTIVATEs the next bank (safe with the interlock and `wvalid`).
* **Write data (pull, fixed lead):** the scheduler raises `w_next` for one cycle per word, `W_LEAD` cycles before that word's `wvalid` cycle at the PHY (**`W_LEAD` is measured to the scheduler-to-PHY `wdata` cycle, not to the pins; default 2**). The client presents `w_data[15:0]`, `w_be[1:0]` exactly `W_LEAD` cycles after `w_next`; `w_idx[9:0]` is valid with `w_next`. The client cannot delay a beat; a client that may not have the data buffers the whole request first.
* **Read data (push):** `r_valid`, `r_data[15:0]`, `r_last` (the last word of the request); **gaps in `r_valid` may occur anywhere inside a request** (splits), order kept. **Read credit:** a client asserts a read only when its FIFO free space is at least its outstanding read words plus `req_len`.
* **Completion:** `done` (one cycle, with `req_tag`): for a read **in the same cycle as `r_last`**; for a write **one cycle after the last beat is registered to the pins**. Within a port requests complete in order and a read after a write to the same address returns the new data. Between ports no ordering is promised; clients that need it use `done`. **At reset every in-flight request is dropped: no `done` for it afterwards.**
* `urgent` is a per-port input when the port's `URGENT_CAPABLE` parameter is 1; the next arbitration picks that port first.
* Per-port counters (a register block the project provides): requests, words, busy cycles, worst wait (grant minus request), urgent waits above the documented bound, `bad_req`.

## 5. Tau V's scheduler (`tau_sdram_sched_v`) (M5)
Everything below is a **parameter with the stated default**; the defaults marked † are placeholders Tau V must confirm and the replay (7.4) may change. Nothing is left for the author to choose.
* **Policy:** open page per bank; a row is precharged only on a row conflict, an aged row (60 us), before a `REF` or on `banks_closed` handling. **Bank = `addr[11:10] ^ addr[21:20] ^ addr[23:22]`** (default; parameter `BANK_HASH`: 0 plain [11:10], 1 `^ addr[21:20]`, 2 the default, 3 a per-picture base skew supplied by the client; **the replay chooses**); row = address[24:12]; column = address[9:0]. Reason (Tau V, 2026-10-28): picture bases 2^22 words apart differ only in bits 24:22, so `[21:20]` alone cannot separate a reference from a reconstruction picture; the default separates consecutive 2^22 bases (bits 23:22) and the player's 2^20-apart buffers (bits 21:20). Bases 4 apart (k and k+4) still collide: the skew option covers them.
* **Look-ahead 2 means: the heads of the per-port request queues, across ports.** After the current grant is chosen, the scheduler picks the next grant by the arbitration rules and may `ACT` its row (when `ok_act` is set) while the current burst is still streaming, provided the target bank is not the current burst's bank and **no queued request wants the row it would close** (a `PRE` never hits a row that any queue head or the current grant needs).
* **Bursts:** full page ended by `BST` or the next column command at the exact word, `BURST_MODE` = FULL_PAGE; a chained-BL8 variant is judged by the replay and not specified here. Chained column commands to an open row leave no idle cycle on the data bus.
* **Arbitration:** urgent port first (including the split pieces of its own request); otherwise **weighted round robin**, weights decoder ports 4, engine 2, CPU 1, DMA 1†, **granted per piece**: the maximum piece is 64 words for decoder ports and 128 for the engine; a request longer than its maximum is served in pieces, each piece a new arbitration. Same-row pieces of the same port are granted back to back unless another port has waited more than 60 us.
* **Queue depth** 4 per port†. **Direction batching:** per port pair (a decoder's read port and write port form a pair), writes are drained when the pair's write queue reaches 8 words-of-requests† (a count of requests) or when an idle gap occurs; a write batch counts as **one grant** (so the urgent bound below includes the longest batch: a write batch is limited to 4 requests and 128 words) and a write's `done` is delayed at most 2 us.† The direction-hold input of v0.1 is **removed**.
* **2D requests (optional on one port):** `req_w[9:0]` words per row, `req_h[9:0]` rows (1..16), `req_stride[24:0]` words between row starts; the scheduler runs each row as a request (page splits as usual). `w_idx` counts words within the row and restarts per row; `r_last` marks the last word of every row; **`done` is one pulse for the whole block, one cycle after the last row's `r_last` (read) or last beat registered (write)**. A row that crosses a page is split. The client issues one request per block instead of 4 to 12.
* **Refresh:** as 3.7, one per idle gap, never while an urgent request waits.
* **Urgent bound (to be documented in the interface document with the final numbers):** W = L_max + tWR 2 + tRP 2 + tRFC 10 + tRCD 2 + read/write turnaround about 3 + RD_LAT about 6 + port registers 2 = **about L_max + 27 = 155 cycles at 128 words (est.)** = 1.55 us, against the 22.7 us line period of an 800x720 scan-out. Measured against the formula (7.3).
* **Overhead target:** at most 2 controller cycles per request over the device's own timing on a stream of short requests to open rows; acceptance is the real-time criterion of 7.4, the overhead is reported, not gated.
* **Ownership (owner's decision, 2026-10-28, D-T10): this project builds everything (PHY, chip model, replay harness, `sched_v` v1 as the reference, `sched_a`); after the tag Tau V owns `sched_v`, Tau Alpha owns `sched_a` and the common elements (PHY, chip model, replay tools).** this project writes `sched_v` v1 from this contract as the reference implementation and tags it; **Tau V owns it from the tag** (D-T09) and may change it; the clean-room rules apply to v1's author. **Ports:** `NPORTS` >= 6. **Budget (est.):** under 2,000 ALMs and 4 M10K, measured by 7.5.

## 6. Tau Alpha's scheduler (`tau_sdram_sched_a`)
Three ports (scanout fill, urgent; the draw engine; the CPU bridge), the section-4 protocol; simple open page, the same bank function; the CPU keeps today's single-word semantics (a 32-bit access is one 2-word request with four byte enables, acknowledged on `done`); the engine's `wsrc_addr` pull maps to `w_idx` with `W_LEAD` = 2; MMIO counters replace the busy-cycle counter; the old controller stays selectable until the soak passes (D-T08). Acceptance: the player's own recorded traffic (not slower, CPU word latency lower), `GFX SCAN LATE` 0 on a Pocket, the soak (`SOAK FAILS` 0, over 30 minutes, warm), the owner's warm soak. Details when `sched_v` is accepted.

## 7. Verification (before a tag)
1. **Chip model** (`sim/sdram_chip_model.sv`, written independently from the datasheet and this contract). Verilator is cycle-based and cannot simulate tAC/tLZ/tHZ or board delay, so **the model checks timing analytically in picoseconds**: for every DQ transition, the chip's drive window against the FPGA's output enable (the conflict assertion), and the capture edge against the valid window (tAC..tOH plus the board delay) **at the minimum and maximum delay and in both `CAP_MODE`s**; every timing rule of 2 and 3.4 per clock; illegal commands, A10 on a column command, init order (CKE, NOP count, MRS, EMRS), BST with no burst, wraps, deep power-down and clock suspend entries (CKE low or RAS H CAS H WE L with CKE low: errors); per-row tREF (8,192 timestamps) and tRAS(max); a data model with byte masks and the exact word count of a burst. A vendor behavioural model kept **outside the repository** is a test-time cross-check. The OLD controller runs through the model first as a baseline finding (expected: the tRFC violation at least); the model's author may not read its source, the test bench instantiates it as a black box.
2. **PHY tests:** init and reset in a burst, every command, the interlock with a **directed driver that offers illegal commands** (each must become NOP + fault, never reach the chip), the permits against the chip model, refresh debt, preemption and `banks_closed`, aged rows, turnaround and the conflict assertion, `RD_EXTRA` 0..2, CL 2 and 3, both `CAP_MODE`s, **mutation tests (at least ten: each rule of 3.4 broken makes a test fail)**, and `phy_fault` = 0 over all scheduler tests.
3. **Scheduler tests (`sched_v`):** every request length 1..512 plus the rejected 0 and 513..1023, page splits, byte enables, order and `done` semantics across ports (a CPU read after an engine write that was `done`), all ports at once, a refresh at the debt limit under urgent load, the urgent bound against the formula, mutation tests.
4. **Replay (throughput), `sim/sdram_replay/`** (harness in progress in a worktree: a stream master, a data endpoint that pulls write data and checks reads, a reference scheduler to prove the harness and a golden model). **Timed `.treq` format** (16 bytes: port, direction, words, address, release time in ns, flags; flag bit 0 = fence: nothing outstanding on its port; one in-order stream across the decoder's ports): **Tau V supplies macroblock and picture markers, deadlines, decode-ahead depth and cross-port fences before the real-time replay can exist.** Until then the untimed `tnv3_tears_q30_48pic.req` and `scan_800x720_1frame.req` replays run as in Tau V's 6.3 and 6.4 and report the cycle count, the commands per request and the burst-tail waste. The real-time criterion: macroblocks released at 67,500 a second against per-picture deadlines, scan-out urgent, a CPU port reading a word every 2 us, a 2 MB/s DMA port, refresh; **pass = no missed deadline and no underflow with at least 10% slack at 100 MHz, where slack means the headroom between the busiest picture's cycle count and its deadline**; worst-case traces from Tau V (all-bi quarter-pel B pictures with worst alignment, a static all-skip scene, a scene change, an I-picture burst); the per-picture distribution (p50, p99, max). Overhead per request reported.
5. **Area and Fmax probe:** synthesis-only Quartus of the PHY + `sched_v` at 6 ports (est. under 2,000 ALMs and 4 M10K) and its slack at 100 MHz with the real SDC at both corners.
6. **On a Pocket** (the player's unit, then Tau V's test core): the soak (all ports active, pattern write/read over the whole 64 MB), CL2 then CL3 at 100 MHz, a sweep of `RD_EXTRA` and of the capture mode (**the chip clock has no phase parameter in this PHY; a chip-clock phase sweep is part of the later PLL variant, which is where it can be swept**), the passing window width as the margin, then 133/150 MHz only after 100 MHz passed. Staging: one port closed page, then open page, then several ports, then refresh postponement, then a clock change.
