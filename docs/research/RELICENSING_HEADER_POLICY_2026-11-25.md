# Header and SPDX policy for the Apache-2.0 move (proposal, 2026-11-25)

**Evidence label: HOST-ONLY. A proposal; nothing is applied, no checker is written.** Companion to `RELICENSING_PLAN_APACHE2_2026-11-25.md` (phase 2 writes the checker, phase 4 turns the policy on). Not legal advice; the exact wording of notices is for the owner or a lawyer (plan Q3, Q9). The SPDX identifiers below are used from memory of the SPDX list (`Apache-2.0`, `MIT`, `CC0-1.0`, `OFL-1.1`, `LicenseRef-<name>`); they were not checked against the list on 2026-11-25.

## 1. Starting point (measured)
Of 726 `.c/.h/.sv/.v/.py` files under `fw2`, `src/fpga/core`, `tools`, `sim`, `sdk`, essentially none carries a licence line, and no file contains `SPDX`. Only 14 tracked files outside LICENSE copies mention a copyright or licence. The licence today is the root `LICENSE`. The policy therefore applies **to new files and files created after the switch**, plus a marked set of third-party and MIT-origin files; a one-time sweep of existing owner-authored files is optional (plan phase 7).

Holder line: `Copyright 2026 Abel Santos` is a placeholder for the owner's choice (plan Q9: the current LICENSE says "alfatreze (Tau modifications)").

## 2. Header text for new owner-authored files

Two lines, SPDX first, then the copyright line. No licence boilerplate in each file (the root `LICENSE` is the text; Apache-2.0's own Appendix allows the short form pointing to it; the owner or lawyer may prefer the full boilerplate, which is then used verbatim from the Appendix of the licence).

| Language | Exact header |
|---|---|
| C, C++, C headers, JavaScript (`.c .h .cpp .js`) | `// SPDX-License-Identifier: Apache-2.0` newline `// Copyright 2026 Abel Santos` |
| SystemVerilog, Verilog, `.vh .svh` | `// SPDX-License-Identifier: Apache-2.0` newline `// Copyright 2026 Abel Santos` (above `` `timescale `` and before the module; for `.svh` also above the include guard) |
| Python | after a shebang and an encoding line if present: `# SPDX-License-Identifier: Apache-2.0` newline `# Copyright 2026 Abel Santos` (before the module docstring) |
| Shell | after the `#!` line: `# SPDX-License-Identifier: Apache-2.0` newline `# Copyright 2026 Abel Santos` |
| Makefile, `.mk`, `.qsf`, `.sdc`, `.tcl`, `.yml` | `# SPDX-License-Identifier: Apache-2.0` newline `# Copyright 2026 Abel Santos` |
| Assembly (`.S .s`) | `/* SPDX-License-Identifier: Apache-2.0 */` newline `/* Copyright 2026 Abel Santos */` (works with the C preprocessor and with `riscv-none-elf-as`) |
| JSON | **no header** (JSON has no comments; the licence is the folder's `LICENSE` and, for packs, the `meter.json` field `licence`: `"Apache-2.0"`) |
| Markdown | no per-file header; one line at the end of a standalone spec only if it is distributed outside the repository: `*Licence: Apache-2.0, see LICENSE.*` |
| Generated files (fonts, ROMs, `fw2/generated/*`) | the generator writes, in its own comment syntax: `GENERATED by <tool> from <input and its licence>. Do not edit.` then the SPDX line of the **input data** and `Copyright 2026 Abel Santos` for the generator's contribution, for example `SPDX-License-Identifier: OFL-1.1` for font-derived tables and `CC0-1.0` for the window-table values |

Year: the year of first creation; no range edits on later changes (a rule that avoids churn).

## 3. Third-party files

A third-party file keeps **its own** header untouched. The policy never edits a vendored file (Helix is pristine plus `tau.patch`, B-1168; the modified files carry what the patch adds).

| Case | Marking |
|---|---|
| Vendored with its own licence text (Helix, picojpeg, VexRiscv, agg23, APF, OFL fonts) | no change to the file; the directory has the licence file (`third_party/<name>/`); a row in `NOTICE` and `docs/ATTRIBUTIONS.md`; the checker reads `third_party/**/UPSTREAM.sha256` where present |
| Third-party file that has **no** licence text of its own (`VexRiscv_Full.v`, the three agg23 files' header-only MIT lines) | a registry entry in `docs/licence_registry.json` (see 5) naming path, licence id, holder and the text file; the file itself unchanged |
| Third-party file the project changed (the five Helix files via `tau.patch`) | RPSL 2.1(c) asks for an Exhibit A notice and a change statement with date in each modified Covered Code file: **a decision for the lawyer** (plan Q5); the policy would add them in `tau.patch`, not by hand |
| Quartus-generated IP (`mf_*`) | Intel's header kept; registry entry `LicenseRef-Intel-Quartus-generated` |

## 4. HarpMudd MIT-origin files

For each file whose text descends from HarpMudd's MIT repository (manifest verdicts ORIGINAL-HARPMUDD and MIXED, shipped or not):

- Keep every existing header line; add, at the top, in the language's comment syntax:
  `SPDX-License-Identifier: MIT` newline `Copyright (c) 2026 HarpMudd` newline `Modifications Copyright 2026 Abel Santos (MIT terms apply to the whole file, see LICENSE-MIT)` for a file kept entirely under MIT; or, once such a file has been rewritten so that no HarpMudd line remains (checked with the manifest tool and `git blame`), the file changes to the owner header in section 2 in the commit that completes the rewrite, and its manifest row is closed.
- **Mixed files** (HarpMudd lines plus Apache lines in one file) are not marked Apache until the plan's Q3 is answered. Default proposal: they carry the MIT form above.
- The list of such files is generated, not typed: `tools/data/harpmudd_manifest.csv` (a copy of the provenance-2026-11-25 manifest with the verdict column), kept current by the existing provenance scripts.
- Files of the `legacy-harpmudd/` tree: MIT form; not shipped.
- The root `LICENSE-MIT` holds HarpMudd's and the earlier Tau MIT notice verbatim (Gallery's layout).

## 5. Checker specification (`tools/check_licence_headers.py`, test `sim/test_licence_headers.py`; **not written now**)

Inputs: `git ls-files`; `docs/licence_registry.json`; the manifest CSV; `third_party/**/UPSTREAM.sha256`.

Registry format (`docs/licence_registry.json`): a list of `{ "path_glob": ..., "spdx": ..., "holder": ..., "text_file": ..., "origin": "third-party|harpmudd-mit|generated|owner-exempt", "note": ... }`. Every tracked file matches exactly one rule: a registry glob, or the default "owner-authored", or the exempt list (binary files, JSON, Markdown, `.gitignore`, generated images, test vectors listed by glob).

Checks (each a numbered failure the test pins):
1. **C1 new/owner files**: every tracked file not matched by the registry and not exempt has the two-line header of section 2 in its first 8 lines (comment syntax by extension table). In phase 2 this runs as a report; in phase 4 it fails only for files **added after the switch commit** (compare with `git diff --name-status <switch-commit>..HEAD` or with a baseline list file `docs/licence_baseline.txt` of the files that existed at the switch).
2. **C2 holder**: the copyright line names the one holder string from `docs/licence_registry.json` `default_holder` (plan Q9).
3. **C3 SPDX id**: the id after `SPDX-License-Identifier:` is in the allowed set `{Apache-2.0, MIT, CC0-1.0, OFL-1.1, LicenseRef-*}`; `LicenseRef-*` must have a registry entry.
4. **C4 third-party**: every file under `third_party/` is either listed in `UPSTREAM.sha256` with the matching SHA-256 (then it must be byte-identical: the existing `sim/test_helix_pristine.py` covers Helix), or has a registry entry; each registry `text_file` exists.
5. **C5 MIT-origin**: every manifest row with verdict ORIGINAL-HARPMUDD or MIXED that still exists carries the MIT header form of section 4; a file with `harpmudd_lines == 0` in a fresh blame report must not carry it (reports stale rows).
6. **C6 no GPL text**: no tracked file other than registered third-party licence texts contains the strings `GNU General Public License`, `GPL-2.0`, `GPL-3.0`, `LGPL` or `AGPL` outside `docs/` and the checker itself (a tripwire for rule 7; it fails the build, the owner decides the exception list).
7. **C7 licence files**: `LICENSE` is the Apache-2.0 text (SHA-256 of the standard text pinned in the test), `LICENSE-MIT` exists with HarpMudd's line, `NOTICE` exists and every `third_party/*` directory is named in `NOTICE.md`.
8. **C8 packages**: `sdk/*/LICENSE`, each `meter.json` `licence` value and the collected licence text agree with the registry (plan Q8).
9. **C9 release**: `tools/make_release.py check_zip` asserts the LICENSES folder lists every file named in `NOTICE` and hashes equal the repository files.

Test (`sim/test_licence_headers.py`, red then green, host-only):
- green: a fixture tree (temp dir, `git init`, a handful of files per language) with correct headers passes;
- red cases, each must fail with the numbered code: missing header on a new `.c`; wrong holder; unknown SPDX id; a changed byte in a vendored file; a `third_party` file with no registry entry; a stale MIT header on a file with no HarpMudd lines; a GPL string in a source file; a missing `LICENSE-MIT`; a zip without the LICENSES folder.
- plus one run against the real tree in report mode that must exit 0 and print counts per class (owner / harpmudd-mit / third-party / generated / exempt / unclassified), unclassified must be 0 in phase 4.

Effort: checker about 250 lines, test about 150 lines, registry and baseline files generated once by the checker's `--init` mode; about 1 day including the first classification of the 2,447 tracked files.

## 6. Where the header text lives (so there is one copy)
`docs/HEADERS.md` (new at the switch, from section 2 verbatim) is what `CLAUDE.md` and `AGENTS.md` point to; no new rule number is needed (rule 9 style lines can be added by the owner). A new-file template for each language goes into `tools/templates/` only if the owner wants a generator; not part of this proposal.
