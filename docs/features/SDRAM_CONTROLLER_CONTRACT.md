## 0. Layers (so each project reuses what makes sense)
```
 clients (decoder, scanout, engine, CPU bridge, DMA)        <- project code
   |  client port protocol (section 4), identical for every scheduler
 scheduler  (tau_sdram_sched_v : Tau V throughput;  tau_sdram_sched_a : Tau Alpha simple)   <- one per project, same port protocol
   |  command interface (section 3.3): one SDRAM command per clock + write data, with cmd_ready
 PHY + guard  tau_sdram_phy   (pins, I/O registers, clocking, init, refresh timer, legality guard, read capture)   <- shared, frozen per tag
   |  pins
 chip model (sim only) : timing and data checker, written independently of the PHY
```
Rules of the split: the scheduler decides WHICH command and WHEN (policy); the PHY guarantees that nothing illegal reaches the chip (the guard delays an illegal command instead of issuing it, and counts it) and that every pin is registered in an I/O cell. A scheduler bug can therefore cost performance, never the unit.

## 1. Hardware facts the authors need (not derivable from the old source)
* **Chip:** Alliance `AS4C32M16MSA-6BIN`, 1.8 V mobile SDR SDRAM, 32M x 16 (64 MB), 4 banks x 8,192 rows x 1,024 columns, 16-bit DQ, two byte masks. Timing facts: `docs/features/SDRAM_PART_FACTS.md` (to be diffed against the MSA datasheet before the PHY is frozen; every number is a parameter in picoseconds).
* **Pins** (`core_top.v`): `dram_a[12:0]`, `dram_ba[1:0]`, `dram_dq[15:0]` (inout), `dram_dqm[1:0]`, `dram_clk`, `dram_cke`, `dram_ras_n`, `dram_cas_n`, `dram_we_n`. **No chip select pin** (the chip is always selected): the command is {RAS#, CAS#, WE#}. All at 4 mA drive; `dram_clk` has a 50 ohm series termination.
* **Chip clock:** `dram_clk` is driven by a DDIO output cell (`altddio_out`, datain_h 0, datain_l 1, clocked by the controller clock `clk`): the **inverse of `clk`**, so the chip samples commands half a period after the controller launches them. Baseline: 100 MHz, CL2. Variants (133/150 MHz CL3) need a PLL output with a tuned phase for the chip clock and, for reads, possibly a capture clock; those are a later variant of the PHY (parameter `CLK_VARIANT`), not a parameter of this one.
* **I/O registers (must):** every output pin is driven by a register that drives only that pin and carries `FAST_OUTPUT_REGISTER ON` (and `FAST_OUTPUT_ENABLE_REGISTER ON` for `dram_dq`, **one output-enable register per DQ bit**); every DQ input is captured by one register per bit with `FAST_INPUT_REGISTER ON` whose only fanout is the PHY's read pipeline. The assignments live in the QSF next to the existing drive-strength lines; the PHY's RTL structure must make them possible (fanout 1). The SDC (`core_constraints.sdc`) carries a generated clock for `dram_clk`, output delays for every output from the datasheet (+0.3 ns board margin), and input delays and a derived multicycle relationship for the read path; **every fit reports their slack at slow 85C and fast 0C** (the S0 fit `s0-b905` has the output side; `tools/sdram_sta_probe.tcl`).
* **Power-up** (this part, datasheet "Power On and Initialization"): clock stable and CKE high with NOP/inhibit for at least 100 us, precharge all, at least 2 auto refresh cycles, mode register set; the extended mode register is optional (default full drive strength, full array) and **may** be programmed (drive strength) later. Re-initialisation after a reset in the middle of a burst starts with precharge all.
* **Mode register:** burst length full page (`111`), sequential, CL as parameter (2 or 3), write burst mode programmed burst (not single-location write), reserved bits 0. CL2 requires tCK >= 9 ns (110 MHz max); CL3 up to 166 MHz.
* **Refresh:** 8,192 auto refresh commands per 64 ms; one every 7.8125 us distributed, or bursts, both allowed; tRFC 97.5 ns; **a refresh debt counter (maximum 8)**, repaid one at a time in idle gaps, never while an urgent port waits; when the debt reaches 8 the next refresh is forced at the next command boundary.
* **tRAS(max) = 100 us:** an open row older than a parameter (default 60 us) is precharged.

## 2. Timing parameters (all in integer picoseconds, converted at elaboration with `$error` checks; no `real`, no `CEIL` macro that adds a cycle to exact ratios)
Converted at 100 MHz (10 ns) and, for reference, 133 and 150 MHz; the PHY computes them, these are the checks: tRCD 18 ns: 2 / 3 / 3; tRP 18: 2 / 3 / 3; tRAS 42: 5 / 6 / 7; tRC 60: 6 / 8 / 9; tRFC 97.5: 10 / 13 / 15; tWR 15: 2 / 2 / 3; tRRD 2 clk; tMRD 2 clk; tCCD 1 clk; tRDL 2 clk; tDQZ (DQM to read data high-Z) 2 clk; tROH (read data high-Z after PRECHARGE) CL clk. Setup/hold at the chip for the SDC: address 1.5/1.0 ns, command and DQM 0.5/1.5 ns, data 1.5/1.0 ns, plus 0.3 ns. Read: tAC 5 ns (CL3) / 8 ns (CL2), tOH 2.5 ns, tLZ 1 ns, tHZ 5 / 8 ns.

## 3. PHY interface (`tau_sdram_phy`)
### 3.1 Parameters
`CLK_HZ` (100e6), `CL` (2 or 3), `RD_EXTRA` (0..2, the number of extra pipeline cycles between the chip's data and the PHY's output: it is what the hardware phase sweep tunes; default chosen from the sweep), the timing parameters of section 2 in ps, `OPEN_ROW_MAX_NS` (60,000), `REFRESH_DEBT_MAX` (8), `INIT_WAIT_US` (100).
### 3.2 Pins
As section 1; `SDRAM_DQ` is an `inout`, driven only by the per-bit output-enable registers.
### 3.3 Command interface (the scheduler's view)
* Inputs, one command per clock: `cmd_valid`, `cmd[3:0]` ∈ {NOP, ACTIVE, READ, WRITE, PRECHARGE (bank), PRECHARGE_ALL, REFRESH, MODE_SET, BURST_TERMINATE}, `cmd_ba[1:0]`, `cmd_a[12:0]` (row for ACTIVE, column and A10 = auto-precharge for READ/WRITE, A10 = all banks for PRECHARGE), `cmd_dqm[1:0]` (the byte mask of the WRITE data of this cycle; for reads see 3.5), `wdata[15:0]` (the word driven in the cycle the PHY issues a WRITE or while a write burst continues: **write data is supplied by the scheduler in the same cycle as the command it belongs to and in every following cycle of the burst; the PHY delays nothing**).
* Outputs: `cmd_ready` (1: the command offered this cycle is accepted and will be on the pins one cycle later; 0: held back by the guard), `rvalid`, `rdata[15:0]` (**exactly `CL + RD_EXTRA` cycles after the READ command was accepted, then one word per clock until the burst is terminated; no backpressure**), `init_done`, `busy_until_ref` (the refresh timer's request: `ref_due` and `ref_debt[3:0]`), counters: `guard_stalls` (commands that had to wait), `guard_violations` (illegal sequences offered that the guard converted into a wait; a correct scheduler never produces any: the testbench asserts it stays 0), `dq_conflicts` (must be 0).
* **Legality the guard enforces** (per bank and global): tRCD (ACTIVE to READ/WRITE, same bank), tRP (PRECHARGE to ACTIVE), tRAS (ACTIVE to PRECHARGE), tRC (ACTIVE to ACTIVE, same bank), tRRD (ACTIVE to ACTIVE, different banks), tWR (last write data to PRECHARGE), tRFC (REFRESH to any command), tMRD, a bank must be idle for ACTIVE and REFRESH/MODE_SET need all banks idle, no column command to a closed bank, tCCD, read/write bus turnaround (3.5), and no command during init except the init sequence's own.
### 3.4 Read path
Every DQ input goes into its own I/O register; the PHY's pipeline adds `RD_EXTRA` more stages and presents `rvalid`/`rdata` aligned as above. `rvalid` is the READ command's burst window shifted by `CL + RD_EXTRA`; a BURST_TERMINATE (or the next READ/PRECHARGE) ends the window at the exact word (the chip model checks the number of words).
### 3.5 Turnaround and masks (must)
Read to write: the PHY holds `dqm` high from two cycles before the first write data until the last read word has left the bus, keeps the DQ output enables off until the read data has finished (tHZ), and inserts the idle cycles the datasheet requires; write to read: the last write data cycle, then tCDL = 1 and the READ. **A simulation assertion proves that the FPGA never drives DQ while the chip drives it** (the chip model gives the drive window including tLZ/tHZ and the board delay); it gates every install. Write masks: `dqm = ~byte_enable` in the cycle of the word (write DQM latency 0); read masks are 0 except as above.
### 3.6 Init, refresh, reset
After reset the PHY runs the power-up sequence by itself (CKE low, clock running, 100 us, CKE high, precharge all, two refreshes, mode register set with the programmed mode, tMRD, `init_done`). A reset at any time restarts the sequence (precharge all first, even in a burst). The refresh timer counts a 7.8125 us interval and raises `ref_due` and a debt (up to `REFRESH_DEBT_MAX`); the scheduler issues the REFRESH commands (it knows when the bus is free); if the debt reaches the maximum the guard blocks all other commands until one REFRESH is accepted (**the only case where the PHY, not the scheduler, forces a command**), so the data is safe even if a scheduler never issues one. Open rows older than `OPEN_ROW_MAX_NS` are reported (`row_aged[3:0]`) and a scheduler must close them; if one reaches 90 us the guard closes it.
### 3.7 What the PHY must not do
No scheduling, no address mapping, no request queues, no knowledge of ports. Everything above is the scheduler's.

## 4. Client port protocol (identical for every scheduler)
Per port `p`:
* **Request:** `req_valid`, `req_ready`, `req_we`, `req_addr[24:0]` (16-bit word address), `req_len[9:0]` (1..512 words; 0 is an error), `req_tag` (optional, returned with the done pulse). Accepted when `req_valid & req_ready`. A request that crosses a 1,024-word page is split by the scheduler; the client sees one request.
* **Write data (pull, fixed lead):** the scheduler raises `w_next` for one cycle per word, **`W_LEAD` cycles before the word is driven to the pins** (`W_LEAD` is a parameter of the scheduler, 2 by default, documented); the client presents `w_data[15:0]` and `w_be[1:0]` exactly `W_LEAD` cycles after `w_next` (a registered FIFO read or BRAM read fits). `w_idx[9:0]` (the beat index, 0..len-1) is valid with `w_next` for clients that address a buffer. The client cannot delay a beat; a client that may not have the data must buffer the whole request first (an M10K FIFO per port).
* **Read data (push, no backpressure):** `r_valid`, `r_data[15:0]`, `r_last`, one word per clock for the words of one request in order (`r_valid` may have gaps between requests). A client that cannot accept the data must buffer it (a FIFO per port).
* **Completion:** `done` (one cycle, with `req_tag`) when **every beat has been driven to the chip** (write) or **delivered on `r_data`** (read): not when the request was queued. Within a port, requests complete in order and a read after a write to the same address returns the new data (the scheduler never reorders within a port). Between ports no ordering is promised; clients that need it use `done` (the player's engine fence uses it).
* `urgent` (port 0 only, optional per port): the client's FIFO is below its threshold; the next arbitration picks this port first.
* Per-port counters (readable through a register block the project provides): requests, words, busy cycles, worst wait (grant minus request), `urgent` waits above the documented bound.

## 5. Tau V's scheduler (`tau_sdram_sched_v`): first deliverable (the owner's order)
Requirements from Tau V v1 as corrected by the reviews. **Policy:** open page per bank, precharge only on a row conflict, an aged row, before a refresh or when the guard says so; **bank = word address bits 11:10 XOR a parameterised function of higher bits** (default `addr[11:10] ^ addr[21:20]`; plain `[11:10]` selectable), row = address[24:12], column = address[9:0]; look-ahead of **2 or more** requests (ACTIVE/PRECHARGE of the next requests on other banks overlap the data of the current one); chained column commands to an open row with no idle cycle on the data bus; **full-page bursts ended by BURST_TERMINATE (or the next column command / PRECHARGE) at the exact word**, with a parameter `BURST_MODE` for a chained-BL8 variant (judged by the replay); refresh as in 3.6 (one per idle gap, never batched while an urgent request waits); **direction batching:** per decoder port pair, writes are drained when a watermark (parameter) or an idle gap is reached, so read/write turnarounds happen once per batch, not once per request; weighted round robin between the non-urgent ports, **granted per request**, with per-port maximum grant length (parameter, default 64 words for decoder ports, 128 for the player's engine) and queue depth (2 to 4); **urgent port 0** wins every arbitration while urgent is held, including the split pieces of its own request. **Ports:** parameter `NPORTS` (at least 6). **Bound (must be documented in the interface document with the final numbers):** worst wait of an urgent request = longest granted request on any other port + tWR + tRP + tRFC + tRCD + CL + capture + pipeline, about L_max + 19 cycles at 100 MHz (147 cycles at 128 words: 1.5 us, against the 22.7 us line period of an 800x720 scan-out). **Overhead target:** at most 2 controller cycles per request over the device's own timing on a stream of short requests to open rows; **acceptance is reconciled with it** (section 7).
**Interface additions Tau V may use:** an optional 2D request type on one port (`req_w`, `req_h`, `req_stride`: rows of `req_w` words, `req_h` rows, a stride), implemented by the scheduler as `req_h` row requests with look-ahead (so the client issues one request per block, not 4 to 12); a direction-hold input per port. Both are optional features of `sched_v` and do not change section 4.

## 6. Tau Alpha's scheduler (`tau_sdram_sched_a`): second deliverable
Three ports (scanout fill, urgent; the draw engine; the CPU bridge), same section-4 protocol; simple open page with the same bank function; the CPU port keeps today's single-word semantics (a 32-bit access is one 2-word request with four byte enables, acknowledged on `done`); the engine's `wsrc_addr` pull maps to `w_idx` with `W_LEAD` = 2; per-port counters on MMIO replace the busy-cycle counter; the old controller stays selectable until the soak passes (D-T08). Acceptance: the player's own recorded traffic replay (not slower, CPU word latency lower), `GFX SCAN LATE` 0 on a Pocket, the soak (`SOAK FAILS` 0, over 30 minutes, warm), the owner's warm soak. Details when `sched_v` is accepted.

## 7. Verification (what must exist before a tag)
1. **Chip model** (`sim/sdram_chip_model.sv`, written independently of the PHY from the datasheet and this contract): every timing rule of sections 2 and 3.3 checked at every clock, illegal commands flagged, a data model with byte masks, **tAC/tOH/tLZ/tHZ and a programmable board delay, run at the minimum and the maximum**, the DQ drive window (for the conflict assertion), the exact number of words of a burst. A cross-check against a vendor behavioural model kept **outside the repository** (test use only). The OLD controller is run through the model first (a baseline finding, expected: the tRFC violation at least).
2. **PHY tests:** init and reset-in-burst, every command and the legality guard (an illegal sequence is held, never issued), refresh debt (including the forced refresh), aged rows, turnaround and the DQ-conflict assertion, `RD_EXTRA` 0..2, CL 2 and 3, mutation tests (at least ten: each rule of 3.3 broken makes a test fail).
3. **Scheduler tests (`sched_v`):** every request length 1..512, page-crossing splits, byte enables, ordering within a port and the `done` semantics across ports (a CPU read after an engine write that was `done`), all ports at once, refresh at the debt limit under urgent load, the urgent bound measured against the formula, mutation tests on the scheduler.
4. **Tau V replay (throughput):** `tnv3_tears_q30_48pic.req` and `scan_800x720_1frame.req` as in Tau V's section 6.3 and 6.4 (copied once to `work/`, referenced by path, commit and SHA-256), **plus the acceptance rewritten by the reviews:** a real-time replay at Level 3 with macroblocks released at 67,500 a second against per-picture deadlines, scan-out urgent, a CPU port reading a word every 2 us, a 2 MB/s DMA port and refresh, pass = no missed deadline and no underflow with at least 10% slack at 100 MHz; worst-case traces supplied by Tau V (all-bi quarter-pel B pictures with the worst alignment, a static all-skip scene, a scene change, an I picture burst); per-picture cycle distribution (p50, p99, max) over the whole film; the cycle count of the original replay reported with the number of commands per request and the burst-8 tail waste counters. **The +10% rule is replaced by the real-time criterion plus a stated overhead per request (target 2, measured, reported).**
5. **Area and Fmax probe:** a synthesis-only Quartus project of the PHY + `sched_v` at 6 ports (budget: under 2,000 ALMs and 4 M10K, an estimate to be confirmed) and its slack at 100 MHz with the real SDC at both corners.
6. **On a Pocket** (the player's unit, then Tau V's test core): the soak (all ports active, pattern write/read over the whole 64 MB at the end), CL2 then CL3 at 100 MHz, a phase/delay sweep of `RD_EXTRA` and the chip clock, the passing window width as the margin, then 133/150 MHz as a PHY variant only after 100 MHz passed. Staging: one port closed page, then open page, then several ports, then refresh postponement, then a clock change.
