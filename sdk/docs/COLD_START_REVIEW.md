# Cold-start review (2026-11-18)

**Method.** A fresh agent (a general-purpose model that had never seen the project) was given ONLY the exported `tau-alpha-meter-template` and `tau-alpha-meter-sdk` trees, in a scratch folder outside the repository, and the task "make a new meter that draws X and builds into a `.tmeter` that passes the suite, using only these documents", with orders to log every place it got stuck or guessed. Three rounds, each with a different X and a fresh agent, after fixing what the last one found. All three finished with suite exit 0 and no failure.

| Round | X | Result | Stuck or guessed |
|---|---|---|---|
| 1 | a horizontal level bar with a falling peak marker, a bool parameter, two presets | success (exit 0, 20 passed) | 12 points |
| 2 | a scrolling loudness history, a number parameter, two presets | success, **but a blocker of my own making**: the template's Makefile was 0 bytes (a regression introduced while fixing round 1: a file opened for writing before it was read) | 6 points |
| 3 | a 4 x 4 grid of cells lit by spectrum bands, text while paused, two presets | success (exit 0, 20 passed, 0 warnings; its own 20-check behaviour test passed); no blocker | 10 points, all minor |

## What each round found, and what changed
**Round 1.** (1) `LICENSE`, `licence`, `homepage` were not explained: GETTING_STARTED now says what to put and that `homepage` may be `""` (the template's fake URL is gone). (2) `thumb` usage: now `thumb [DIR]` everywhere, and `make thumb` passes `.`. (3) `thumb` wrote no `palette_roles`: **the tool now writes them** for every colour that is a reference-theme colour and prints each palette entry with its role; PARAMETERS explains `in->bg` = the theme's `base`. (4) The template's own test failed for any meter that does not use `mtr_bar`: **the test is now generic** (loud differs from silence, a forced repaint is repeatable) and says it is an example. (5) The call-tuple format, the reference colours and the way to drive the runner were undocumented: a "Driving the runner from Python" section in TESTING. (6, 7) State across `force` and the range and meaning of `dt_ms`: added to METER_MODEL. (8) Forced repaints against `cmds`: TESTING says they are printed, not judged. (9, 11) What the four preview frames are, and what the thumb frame is: documented. (10) The suite does not know what the meter should look like: TESTING says so and points to `test/test_meter.py`. (12) fixed with (2).
**Round 2.** (1) the empty Makefile: restored, and `sim/test_sdk_export.py` now fails on any empty template file and runs `make test` in the exported template. (2) What `scroll_left` leaves in the vacated columns: stated in the header (and so in HOST_TABLE). (3, 4) the full list of call forms and the descriptor's keys (`def`, `key`, ...): documented. (5) rounding: left to the author. (6) the extra palette entries of `thumb`: explained in PARAMETERS.
**Round 3.** (1) Text footprint: TESTING says the suite models 7 x 16 and to erase with a margin. (2) A stale list preview passes: documented as not detected (a check would need to render the meter and compare). (3) Placeholders passed: **new warning `PKG-PLACEHOLDER`** for "Your Name" in LICENSE, README or author; GETTING_STARTED names README.md. (4) `u8` with `max` 400: PARAMETERS says both types are carried as 16 bits. (5) the text call format (`'504155534544.'`): documented. (6) `ROLES_DARK` indexing: documented. (7, 8) limits guidance: PERFORMANCE now gives two rules (`cmds` from the worst ordinary picture by reading the code; until measured on a Pocket, ten times the simulator's slowest tick or 200,000, whichever is larger). (9) the preview never shows the paused path: documented. (10) the template test's header comment: fixed.

**What this review does not show.** The reviewer was a language model with a shell, not a person, it never had a Pocket, and each round took about two minutes: it shows the documents carry a stranger from zero to a passing package, not that they are pleasant. The Pocket step ([ON_A_POCKET.md](ON_A_POCKET.md)) was read but cannot be run by anyone without a card write. Known remaining gaps: Windows and Linux install steps are untested ([TOOLCHAIN.md](TOOLCHAIN.md)); the suite cannot judge a stale preview image or a meter's intended look.
