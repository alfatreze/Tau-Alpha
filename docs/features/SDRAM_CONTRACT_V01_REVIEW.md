## Blockers
* **B1 (3.3, 3.6, 7.2) the guard "delay, not issue" cannot be implemented safely.** `cmd_ready` depends on the offered command (a combinational loop with the scheduler, and no way to plan ahead); delaying the command that ends a burst (BST, READ, PRE) lengthens it (a read delivers extra words, a write lays down extra words with whatever DQM is on the pins: corruption); an illegal command (a column command to a closed bank) would be held forever (deadlock); a delayed WRITE meets data that `w_next` already pulled `W_LEAD` cycles earlier. **Fix:** the PHY exports registered "permitted next cycle" vectors (`ok_act[3:0]`, `ok_rd[3:0]`, `ok_wr[3:0]`, `ok_pre[3:0]`, `ok_ref`, `ok_bst`); after init `cmd_ready` is always 1; the guard is an interlock: an illegal offer is replaced by NOP, DQM forced to 11, the DQ output enable turned off, a sticky `phy_fault` set and the offer counted; it never stalls; the verification line becomes "`phy_fault` stays 0".
* **B2 (1 vs 3.6) forced refresh and aged-row closing contradict each other and can deadlock.** Blocking "all other commands until a REFRESH" also blocks PRECHARGE and BST, and a REFRESH needs every bank idle; section 1 says "at the next command boundary", 3.6 says "block"; the 90 us row close is a second forced command (contradicting "the only case"); a row the PHY closes behind the scheduler's back makes the next READ hit a closed bank. **Fix, a preemption protocol:** the PHY raises `preempt`; the scheduler acknowledges at a burst boundary or a timeout of L_max+8 cycles expires; the PHY issues BST (DQM high), PRECHARGE_ALL, waits tRP, then REFRESH; the PHY pulses `banks_closed` and the scheduler clears its open-row table; the event is counted as a fault.
* **B3 (3.3, 3.4) the read latency is wrong and the capture point undefined.** "CL + RD_EXTRA after acceptance" omits the command output register (+1) and the I/O capture register (+1). With the inverted chip clock, E = the clk edge that accepts the READ, the chip samples it at E+0.5; word 0 is valid from E+0.5+(CL-1)+tAC to E+0.5+CL+tOH (before board delay): CL2 E+2.30..2.75 tCK, CL3 E+3.00..3.75 tCK (estimate); no rising edge of clk falls inside either window unless the round trip is at least 2.5 ns plus the hold time, and an integer RD_EXTRA cannot centre it; the falling edge (E+2.5 or E+3.5) fits with about 2 ns each side (estimate). **Fix:** a capture-edge parameter (falling-edge I/O capture, `altddio_in`, or a PLL capture clock); export `localparam RD_LAT` (estimate CL+2+RD_EXTRA from the acceptance cycle) and write every rule against it; put the window arithmetic in section 1.
* **B4 (3.3, 3.5) DQM ownership with full-page bursts is undefined.** A full-page burst never ends by itself; during an open write burst every cycle with DQM low writes `wdata`, and `cmd_dqm` has no signal saying a beat is valid; 3.3 makes the scheduler own DQM, 3.5 the PHY. **Fix:** add `wvalid`; the PHY drives DQM = `wvalid ? ~be : 2'b11` while a write burst is open; DQM is 11 at reset, in init and when idle; the PHY alone owns read-side DQM; byte lanes: `be[0]` = DQ[7:0] = `dram_dqm[0]`.
* **B5 (1 vs 3.6, and the datasheet) the init and reset sequence contradict each other and the part.** 1 says CKE high with NOP >= 100 us, 3.6 says CKE low, 100 us, CKE high; the datasheet says the mode register AND extended mode register set commands must be issued at init (the power-on state may be undefined), the contract calls EMRS optional; dropping CKE with RAS H, CAS H, WE L (the BST encoding) enters deep power-down, dropping it in a burst is a clock suspend (a read burst keeps driving DQ); a core reload looks like a reset in a burst (the previous core's full-page read may still be driving the bus and wrapping). **Replacement text:** "From the first PHY cycle: CKE = 1 (never lowered afterwards), DQM = 11, DQ OE = 0, NOP for >= INIT_WAIT (10,000 cycles at 100 MHz, counted from CKE high); PRECHARGE_ALL; tRP; REFRESH x2 (tRFC each); MRS BA=00 A=0x027 (CL2) / 0x037 (CL3); tMRD; EMRS BA=10 A=0x000 (full drive, full array); tMRD; init_done. A reset runs the same sequence." **Note:** `SDRAM_PART_FACTS.md` says "MRS 0x227-style": that sets A9 = 1 (single-location write); the old controller programs 0x027 (verify).

## Major
* **M1 legality list incomplete** (times are chip edges; READ at r, WRITE at w, n words): read words at r+CL .. r+CL+n-1; BST, READ or PRE at r+n ends a read after exactly n words (CL2 and CL3, tROH = CL); write latency 0, beat k at w+k; BST at w+n (tBDL 1); WRITE or READ at w+n (tCDL 1); PRE at >= w+n+1 (tDPL/tRDL 2) with DQM = 11 at w+n; ACT on the same bank at >= w+n-1+tDAL (tDAL = tWR + tRP = 4 at 100 MHz); tRC also from ACT to REFRESH. Add: any column command to any bank interrupts the current burst; a PRE to another bank does not end it; BST with no burst open counts as NOP; **READ/WRITE with A10 = 1 is illegal** (auto-precharge is "at the end of the burst", which a full-page burst never reaches); a column wrap past 1023 is a contract violation; tRAS(max); per-row tREF. **Remove MODE_SET from the scheduler's commands** (a CL change would invalidate RD_LAT).
* **M2 read-to-write turnaround needs numbers:** L = r+CL+n-1 (the last wanted read word); DQM high from edge L-1; the WRITE (which also ends the read) no earlier than L+2 at CL2 / 100 MHz (tHZ 8 ns: the chip can drive until L+0.8 tCK, the FPGA's enable launches 0.5 tCK before the chip edge): one idle cycle on the data bus (estimate). Write to read: READ at w+n, output enable off after the last beat.
* **M3 refresh interval not exact:** 7.8125 us is 781.25 cycles; with a debt of up to 8 a row can go 64 ms + 62.5 us between refreshes. Use <= 64 ms / 8,200 = 7.80 us (780 cycles at 100 MHz). Split `busy_until_ref` into `ref_due` and `ref_debt`.
* **M4 port protocol open points:** `w_idx`, `r_last` and `done` are per REQUEST, not per grant; gaps in `r_valid` anywhere within a request (page-crossing and max-grant splits), order kept; a read-credit rule (a client asserts a read only if its FIFO free space covers its outstanding words plus `req_len`); `req_ready` registered; `W_LEAD` defined against the scheduler-to-PHY wdata cycle, not "the pins"; `req_len` 0 or 513..1023: assert, count, never hang; a width for `req_tag`; `done` in the same cycle as `r_last` for a read, one cycle after the last beat is registered to the pins for a write; in-flight requests at reset defined; urgent as a per-port `URGENT_CAPABLE` parameter. A 1-word read is READ then BST (or the next column command) at r+1; a 1-word write is WRITE with `wvalid` then BST or a column command at w+1; a page-crossing split re-ACTIVATEs in the next bank (safe only with B4 and B1).
* **M5 section 5 (Tau V's scheduler) cannot be written without guessing:** "granted per request" contradicts the maximum grant of 64/128 for requests up to 512 words and "hold the grant for same-row requests"; look-ahead 2 over what (per-port queue heads, or across ports)?; when may a non-granted request ACTIVATE, may a PRECHARGE hit a row a queued request needs?; batching: which ports form the pair, watermark in words or requests, a maximum hold time for a write's `done`, a write batch must count as one grant or the urgent bound breaks; 2D requests: field widths and units, what `w_idx`/`r_last`/`done` mean per row and per block, rows that cross a page; the direction-hold input is undefined; placeholders to settle: WRR weights, watermark, queue depth, max grants 64/128, look-ahead 2, age 60 us, debt 8, W_LEAD 2, 67,500 macroblocks a second, 10% slack, 2,000 ALMs / 4 M10K.
* **M6 the urgent bound uses the old tRFC (8 cycles):** W = L_max + tWR 2 + tRP 2 + tRFC 10 + tRCD 2 + read-to-write turnaround about 3 + RD_LAT about 6 + port registers 2, about L_max + 27 = 155 cycles at 128 words (estimate): still far inside 22.7 us.
* **M7 verification parts cannot be done as written:** Verilator is cycle-based and cannot simulate tAC/tLZ/tHZ or board delay: the chip model needs analytical interval checks in picoseconds per DQ transition (the chip's drive window against the FPGA's output enable, the capture edge against the valid window, at minimum and maximum delay); per-row tREF needs 8,192 timestamps (a window is 6.4 M cycles); the `.req` format (port, dir, words, address) has no macroblock or picture markers and no dependencies, so the real-time replay of 7.4 is impossible until **Tau V supplies markers and fences**; guard mutation tests need a directed driver that offers illegal commands; 7.6 sweeps the chip clock but 1 and 3.1 give this PHY no phase parameter, and an integer RD_EXTRA sweep (10 ns steps) cannot measure a window width; `INIT_WAIT_US` may be shortened in simulation only if one test runs the real value.

## Minor
Commands setup/hold "0.5/1.5" in the datasheet is probably transposed: use 1.5/1.5 in the SDC; use tOH 1.8 ns (unloaded) as the floor; "all at 4 mA" is correct (the earlier review's DQM remark is outdated); `cmd_valid` vs NOP and PRECHARGE vs PRECHARGE_ALL with A10 overlap; the tag (section 8) comes before any Pocket run: say so in the tag notes; the section 2 conversions (2/2/5/6/10/2) check out.
