## A019/2 · O021/3, one by one
1. **Trust: the owner decided, 2026-11-12: meters are fully independent.** Anyone creates, loads and shares a meter with nobody's approval (D-M20 stands: "anyone may make a pack"); the worst case is that it does not work or is slow. So Omega installs from **a file, or from a URL or GitHub repository the user gives it**, shows author, source (or binary only), licence, hashes and "a meter runs with full access to the player" before every install and update, labels it **independent: not reviewed**, and may offer update notices from the same source the user gave (shown and confirmed, never silent). **On top of that there is an optional verified tier:** the catalogue `tau-alpha-meters` lists meters submitted as source (pull request), built by CI, conformance-tested and reviewed, with a **signed `index.json`** (ed25519, the project key; Omega ships the public key and labels a meter "verified" only if the signature verifies) and a `revoked` list for verified meters. We had accepted your "no catalogue until `signature` is checked" without asking the owner and withdraw it. The firmware adds a **safe boot** (a meter active at a watchdog or reset is not selected at the next boot) and never auto-selects a newly installed meter; the spec states plainly that a hostile meter is not contained (section 2, commit `f160bebc`). **Asks of you: A019/Q-2.**
2. **Ids and collisions: changed by the owner (2026-11-12): a meter's id is 128 random bits (32 lower-case hex digits), made once by the SDK, no registry and no naming rules.** `id_hash` is the first 32 bits of the id (no FNV). Omega still refuses to install a meter whose `id_hash` equals another installed meter's (different id), and the firmware may assume unique hashes. **A random id proves nothing about who made the meter**, so Omega must treat an update as an update only when the source is the same as the installed meter's (author field, or the URL or repository the user gave); the same id from another source is shown as "same id, different source" and needs a separate explicit confirmation. A fork makes a new id. Our seven shipped meters get fixed ids, listed in the collection repository.
3. **Names: taken, stricter than you suggested.** Printable ASCII `0x20..0x7E`. We could not confirm from the code that the font draws all of code page 437, so we start with what we know; it can widen later.
4. **`id[40]`: settled by the new id:** exactly 32 hex digits, always NUL-terminated.
5. **Preview: answered.** The package carries `preview.png`, exactly 56 x 32, at most 8 distinct colours; Omega converts it to the bin's preview block (an 8-entry palette plus the run-length stream) and refuses a file that does not fit. We do not ask Omega to render meters.
6. **Presets: answered, and we corrected our spec.** The presets are the existing binary files (`index.tpi`, `p<id>.tpr`, `fw2/cores/mpreset_core.h`, `tools/player2/mpreset.py`), not JSON as our first draft said. Folder: the 32-bit id hash in 8 lower-case hex digits (today it is the decimal manifest index). The `meter id` u16 inside the files becomes the hash's low 16 bits (informational). Open for P2: whether the firmware keeps reading the old decimal folder for the seven shipped meters; Omega would move them when it composes the bin.
7. **`persist_layout` 2: taken.** `tau-compat.json` will say `persist_layout` 2 when it ships; a layout-2 card is read only for Omega until its mirror ships. We supply the golden vectors and the staged captures **before** the firmware lands (they come from the migration test, as B-845).
8. **256-byte TOC entry: kept** (room to grow; it is 16 KB in PSRAM at 64 meters).
9. **Package limits: taken** (zip at most 4 MiB, no path outside the package, no file beyond the table, `meter.bin` at most the window, every file pinned, refusal in plain words). Tell us if you want a different cap.
10. **Shared bin: yes.** `tau-meters.bin` in `common` is read by every Tau core on the platform (TAU, TAU Diagnostics, TAU Preview reads TAU's media in place).
