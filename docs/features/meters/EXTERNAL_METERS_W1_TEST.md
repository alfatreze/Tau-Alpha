# TAU DEV 226: the METERS menu and Configure of any meter on a Pocket (W1 of 0.7.5), ONE session of about 15 to 20 minutes

**What changed (decision D-M25, plan `RELEASE_075_PLAN.md`):** the meter list is no longer in Settings > Appearance. It is its own entry of the main menu, **METERS, directly below APPEARANCE**, and opens on the meter that is on screen. Appearance has no METER and no METER: CONFIGURE row any more. In the list **A sets the meter, X configures the highlighted one** (any meter that has parameters, not only the set one), and every configurable row has a small **gear** at the right. Configure of a meter that is not the set one shows **that meter live** on its page and, when you leave the page, **the set meter comes back**; Configure never changes which meter the card remembers. Start+X on Now Playing still configures the meter on screen. What Configure edits now goes through one settings interface (`meter_settings_get/put`), still backed by the pool of **two** tunings: **only two meters keep their settings across a restart** (known limit until the save file of W2). No bitstream change (`4D50331B`).

**Package (built, NOT installed):** `work/diagnostics/tau-dev-226` in the W1 worktree (`.claude/worktrees/w1-meters-menu-270769/work/diagnostics/tau-dev-226`; copy it to the main working copy before installing). This is the **NORMAL build** (`DIAG=0`), the one that ships: `PLAYER2=1,FLAC2=1,LPC=1,PACKS=1,DIAG=0,RAM_192K=1,CLK66=1,SDRAM_BUSY=1`, bitstream `wdog-w3` (`4ce03b2c...2245`, `CORE_VERSION 4D50331B`), version `0.7.1-dev.226+2234e86e`. Free hot RAM **5,840 B**, the same as DEV 225.

**Card:** install with `tools/install_dev_core.py` (dry run, your approval, `--card /Volumes/Pock`, `--remove "alfatreze.TAU DEV 225"`). Then, **with your approval**, copy the 64-row bin as `Assets/tau/common/tau-meters.bin`. Build it with

```bash
python3 tools/make_synthetic_meter_bin.py work/w1/bin64 --rows 64 --unavailable 20 --hidden 21
```

and copy `work/w1/bin64/tau-meters.bin` (not the `-hang` file; SHA-256 `7b0f6237...2e64`). Its rows: Winamp Bars, Winamp Scope, Chladni, Layered Wave, VU Master, Waterfall, Sound Map, then TEST 08 to TEST 64. **TEST 20 is UNAVAILABLE** (asks for a newer TAU: greyed), **TEST 21 is HIDDEN**. Each TEST n runs as (n - 8) mod 6: 0 Scope, 1 Chladni, 2 Layered Wave, 3 VU Master, 4 Waterfall, 5 Sound Map (TEST 12 = Waterfall, TEST 14 = Scope, TEST 15 = Chladni, TEST 22 = Layered Wave). The list holds **63 positions** (position 1 Winamp Bars, 2 to 7 the real meters, 8 to 20 TEST 08 to TEST 20, 21 = TEST 22 ... 63 = TEST 64).

Start a long playlist and keep it playing. **Pause before every screenshot** (a screenshot while playing adds one dropout).

## What I read from the photos
About: METER = the set meter, **METERS = `64 METERS`**, SETTINGS = **OK**, AUDIO **NO DROPOUTS** (before any screenshot), CARD READS **NO ERRORS**, no `(A METER FAILED)` unless you picked a meter that failed.
Report (normal build, the support set): `PACK FILE` **0**, `PACKS SEEN` **64**, `PACK SRC` **1** (the user's file), `PACK ERR` **0**, `PACKS STRUCK` **0**, `METER CUR` the meter on screen (the SET meter, never the one last configured), `PACKS RUN` a bit for the row in the window now, `SET LAYOUT` **2**, `UNDER RING` and `DRY` **0** before the screenshot, `SLOT ERR` / `SLOT OPEN FAIL` / `ST FAILS` **0**. (`MSEL`, `MWIN`, `MTOC` rows exist only in the Diagnostic Build: the commit rule and the load counts are host-tested for this change, not visible here.)

## Bad signs (tell me which step)
The gear overlapping a name, the `*`, the `!` or `N/A` (or unreadable in Light mode); a gear on the greyed row; a row of the list without a gear that has parameters; **the `*` or the saved meter moving when you only configured** (steps 4, 7); the set meter not coming back after B or Start (a different meter on Now Playing, or Winamp Bars after a failure); a leftover of the configured meter's picture on Now Playing; a stutter or dropout at the load when pressing X or leaving the page; Configure of a non-set meter showing the wrong meter or the wrong parameters; a freeze; the restart coming back on the meter you only configured; more than two meters keeping their settings, or fewer than two (step 8); METER or METER: CONFIGURE still in Appearance; INFO or DIAGNOSTICS on Home.

## What the host could not test (so this session is the first look)
The real font drawing and exact pixels (the host used the fonts' advance tables and a model of the screen: the gear is 11 x 11 at x 304 to 314, names end before x 300, marks start at x 316 or later in all four fonts); the look of the gear in the two themes; the time of a Configure open (one pack load, about as long as pressing X on Now Playing) and of leaving it (a second load); the real SD with the music stream mid-read (host model: a read in flight at every load, quiesced first, no collision); a **meter with no parameters** (no shipped or synthetic meter lacks them, so "X says `THIS METER HAS NO SETTINGS`" is host-tested only); a **damaged pack** at Configure (`CANNOT OPEN THIS METER`, also host-only here; `tau-meters-hang.bin` is for the watchdog and is not part of this session).
