Yes:** each `<key>_wasm.js` is a plain script that carries its WebAssembly bytes inside the file, so no fetch and no file read outside the page; your `allow-scripts` frame is enough.
- **O007/Q-026: per meter folder, confirmed for Omega's installs.** A meter folder that already has an `index.tpi` is the owner's; seed a meter with no index whole. Per-file seeding would bring a deleted preset's file back or overwrite a reused id, as you say. Our side: the release zip is a plain zip (unzipping restores every missing factory file, which is what a user who wants the factory set back does). **A009/1, a fix because of your question:** `tau_compat.py check-card` reported a missing `tau-presets/` file as an **error**, so a preset you remove from the card (your D-022) would have failed our card check. It is now a **warning** (red first in `sim/test_tau_compat.py`); a changed hash was already only a warning.
- **O007/Q-027: confirmed.** The remembered preset fields (`SF_MPRE0..6`, `SF_MPID0..6`) are indexed by the meter **table slot**, not the manifest id. A pack descriptor holds the manifest id at offset 32 and the slot at offset 34, and the firmware refuses a pack whose slot is not its position in the table (`MPK_E_DESC`), so for a pack-only meter the slot in the descriptor **is** its table slot; the built-in meter, Winamp Bars, is slot 0 (manifest `p2.slot` 0). Deriving slot to manifest id from the descriptors on the card plus slot 0 is the intended way. Limit to know: the remembered fields exist for slots 0 to 6; a meter in a slot above 6 would have no remembered preset (seven meters ship today).
- **O007/Q-031: previewing a preset in the lab: not possible today** (`index.html` has no `postMessage` or URL-hash handler); accepted for the new drop. Proposed shape, for your confirmation: parent to frame `{type:"tau-lab-set", meter:<manifest id>, values:{<parameter key>:<integer>}}`, frame to parent `{type:"tau-lab-ready", meters:[<manifest id>...]}` once the modules are compiled; an unknown key is ignored and a value is clamped to the parameter's range, as the firmware does; the sandbox stays `allow-scripts`.
