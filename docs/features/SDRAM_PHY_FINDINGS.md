# SDRAM PHY: findings (ambiguities in the contract, assumptions taken, limits of the tests)

Author: the PHY agent, clean-room (contract v0.3 sections 0-4, 7.2, 8; `SDRAM_PART_FACTS.md`; `SDRAM_CHIP_MODEL_FINDINGS.md`; `sim/sdram_chip_model.sv` and its tests as the checker). RTL: `src/fpga/core/tau_sdram_phy.sv` (top, DQ tri-state, DDIO clock), `tau_sdram_phy_core.sv` (all logic and the pin registers), `tau_sdram_dq_cap.sv`, `tau_sdram_clk_out.sv`; Quartus assignments as a snippet in `src/fpga/core/tau_sdram_phy_assignments.txt` (the QSF was not edited). Tests: `sim/sdram_phy/` (`run_tests.sh`, `Makefile`). **Everything here is simulation only: nothing was run in Quartus or on a Pocket, and no Quartus timing is claimed.** The sibling datasheet was not diffed against the MSA sheet (open point 9a of the contract is untouched).

Each point: what is unclear, the readings, the assumption the PHY took. Flag **ask** = the owner or the contract author should decide.

## Optional features of contract 3.7b (CALIBRATE, PERF, BIST): findings and assumptions
All three are parameters, default 0; with 0 the ports are constant and the 88 original PHY tests, sched_v's 55 and the replay (clip, 1 picture) are unchanged. Tests: 120 pass in `sim/sdram_phy/run_tests.sh` (108 in the CALIBRATE/PERF commits plus BIST), 33 mutants killed; `sim/sdram_phy/lint.sh` runs Verilator -Wall (default and each feature on): 0 warnings. Simulation only.

| # | Point | Assumption taken | Flag |
|---|---|---|---|
| F1 | CALIBRATE sweeps `RD_EXTRA` 0..2 | `RD_EXTRA` only adds stages after the capture register, so in the chip model every extra count passes or fails together; a sweep of it alone cannot show a margin. The sweep is therefore six settings: capture edge (FALL, RISE) x `RD_EXTRA` 0..2; `cal_window[k]` with k = 3*(RISE) + extra (bits 7:6 are 0), `cal_best` the same index. Best = the edge with more passing settings (tie: the configured `CAP_MODE`), then the middle of its range. With CALIBRATE = 1 both capture registers exist (each DQ pin has fanout 2, so the fanout-1 `FAST_INPUT_REGISTER` packing is lost in that variant; documented in `tau_sdram_dq_cap_dual.sv`). `rd_lat` becomes dynamic (port) and `RD_EXTRA`/`CAP_MODE` are the settings used until calibration ends or when none passes | ask |
| F2 | Calibration region | the PHY has no address map: the region is a chip-coordinate row (`CAL_BANK` 3, `CAL_ROW` 8191, first `CAL_LEN` = 64 columns). The scheduler's map must reserve that row (the contract's last 8,192 words contain it only for a map that puts bank 3 / row 8191 there) | ask |
| F3 | Calibration flow | after the EMRS and tMRD: ACT, write the pattern, BST, then for each setting a read of `CAL_LEN` words checked word by word (a setting passes if every word matches and exactly `CAL_LEN` words came back), PRE, then `init_done`. No pass: `cal_fault`, sticky `phy_fault` cause 13, the parameter setting stays, `init_done` still rises (no deadlock). A reset re-runs it | info |
| F4 | Bus ownership | CALIBRATE owns the bus inside the init. BIST: a rising edge of `bist_start` is remembered; the run starts in the first cycle with `idle_ok` = 1, every bank closed and past its timing, the scheduler offering NOP and the forced-refresh sequencer idle. `idle_ok` is sampled at the start only. While `bist_busy` all permits are 0 and a non-NOP offer is NOP + fault (cause 12). The refresh duty is kept by the engine (REF before each page when `ref_due`) and the preemption trigger is off while it runs | ask |
| F5 | BIST range and patterns | range = parameters `BIST_PAGE_LO/HI` (inclusive, page = row of one bank = 1,024 words, index `{row, bank}`), default the whole 64 MB. Four passes per page range: write hash(address), read and check, write its complement, read and check (finds stuck bits of both polarities and address aliasing, not coupling faults). `bist_errors` counts failing words (a missing or extra word counts one), `bist_first_addr` = `{bank, row, col}` of the first. A full 64 MB run is about 135 million clocks (not simulated; the tests use 2 pages = 8,484 clocks) | info |
| F6 | PERF definitions | a row hit is a column command to a row that already had one since its ACT, a miss the first after an ACT (the PHY cannot see requests); r2w/w2r = a WR after a RD / RD after a WR (last column command); a bank-conflict stall = a NOP cycle while some bank still waits for tRCD, tRP or tRC; idle = NOP cycles after init_done; gap bins 0,1,2,3,4-7,8-15,16-63,64+ NOP cycles before each command. 32-bit, wrap at 2^32, flat 512-bit `perf_snapshot` (word i = bits 32i+31:32i: ACT, PRE, hit, miss, r2w, w2r, stall, idle, bins 0-7), `perf_snap` strobe, `perf_clear`. Counted after `init_done`, including the PHY's own forced and BIST commands | ask |
| F7 | PERF check | the chip model has no ACT/PRE counters, so the tests compare with an independent decoder on the chip pins (validated against the model's WR burst count); commands and bins exactly, idle and stall within 4 cycles (start/stop alignment) | info |
| F8 | New inputs left unconnected | existing instances (sched_v, replay) leave `idle_ok`, `bist_start`, `perf_*` unconnected; they are unused while the parameters are 0 | info |

## Results the tests produced
* Measured `RD_LAT`: FALL CL+2+RD_EXTRA, RISE CL+1+RD_EXTRA (CL2 and CL3, RD_EXTRA 0..2), identical to the formula the PHY exports (chip-model finding A8).
* Earliest `WR` after a terminated read: BST + 3 clocks at CL2 and CL3 (found by polling `ok_wr`, then confirmed conflict-free by the chip model).
* A write directly followed by `RD` at w+n reads back the data at CL2 and CL3 with no bus conflict.
* Refresh: debt increments every 780 clocks; with no scheduler the PHY forces one REF per interval (`tref_idle`, 66 ms, see the run log of the final report); the chip model reports no tREF error.
