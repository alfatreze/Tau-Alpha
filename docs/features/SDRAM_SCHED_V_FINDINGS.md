# SDRAM scheduler `tau_sdram_sched_v` v1: findings (ambiguities in the contract, assumptions taken, limits of the tests)

Author: the sched_v agent, clean-room (contract v0.6 sections 0, 3, 4, 5, 7.3, 8; PHY and chip-model findings; the PHY RTL ports and permits; the PHY test bench for instantiation; the sibling-part datasheet text). No existing controller RTL, its history or replay fragments were read. RTL: `src/fpga/core/tau_sdram_sched_v.sv`, `tau_sdram_sv_pq.sv` (per-port queue and piece generator), `tau_sdram_sv_arb.sv` (arbiter). Tests: `sim/sdram_sched_v/` (`run_tests.sh`). **Simulation only: nothing was run in Quartus or on a Pocket; no area, Fmax or timing is claimed.** The replay (7.4) was not run.

Each point: what is unclear, the readings, the assumption taken. Flag **ask** = the contract author or Tau V should decide.

| # | Point | Readings | Assumption taken | Flag |
|---|---|---|---|---|
| S1 | Request fields not in section 4 | 2D needs a flag; BANK_HASH 3 needs the skew | extra per-port inputs `req_2d`, `req_skew[1:0]` (sampled with the request). A `req_2d` request on a port whose `ENABLE_2D` bit is 0, a 2D write, `req_w` or `req_h` 0, or `req_w*req_h` > 512 is rejected (`bad_req`, immediate in-order `done`). Skew: bank = addr[11:10] ^ skew; the client must give every access to the same address the same skew | ask |
| S2 | `w_idx` for 2D | 5 says `w_idx` counts over the whole 2D request, but `w_idx` belongs to write pulls and 2D writes are out of v1 | `w_idx` is only driven with `w_next`; 2D reads carry no index. `r_last` and the single `done` are per request | info |
| S3 | Which ports exist | section 5 names decoder read/write, engine, CPU, DMA, scan-out | defaults: port 0 scan-out (urgent capable), 1 decoder read (max grant 64, 2D), 2 decoder write (max grant 32, batched), 3 engine, 4 CPU, 5 DMA; WRR weights 4,4,4,2,1,1 (port 0 and the others not named in the contract: 4 and 1 are dagger placeholders). Per-port masks are 8-bit parameters, `NPORTS` 6..8 | ask |
| S4 | "Urgent port 0" | port 0 always first, or only while `urgent` is up | the `urgent` input of a capable port is the only urgency; port 0 without `urgent` competes by weight | ask |
| S5 | Write batching threshold "8 words-of-requests (a count of requests)" with queue depth 4 | cannot be reached | a batched write port (decoder write) is eligible when `WR_HI_REQ` (2) requests are queued, or its head waited `WR_DEFER_NS` (1000 ns, so a write `done` is delayed by about 1 us plus service), or no other port has a candidate. A write grant (batch) = up to 4 requests / 128 words from one port, committed together and not interrupted (not even by an urgent port); it counts as one WRR grant. Weights therefore count batches for a batched port | ask |
| S6 | Write `done` "one cycle after the last beat is registered to the pins" | cycle t+1 or t+2 for a beat offered in cycle t | `done` is visible in cycle t+1 (the cycle after the last `wvalid` cycle); the tests compare the chip's memory at that cycle (the chip samples the beat half a cycle into t+1) | ask |
| S7 | Read-to-write needs a BST first (PHY P4) | the batch commits early to hide it | a write grant is committed (words pulled) `W_LEAD+2` cycles before the end of the burst in progress, or at once when idle; read to write costs BST + 3 (the pull overlaps it). A write directly after a write, and a read directly after a write, chain with no idle cycle | info |
| S8 | Write data pull and `W_LEAD` | client answers exactly `W_LEAD` after `w_next`; scheduler needs the word at the PHY in a fixed cycle | words are pulled into an 8-deep skid FIFO; the `WR` is offered only when at least min(n, W_LEAD+1) words of the piece were pulled and the FIFO is non-empty, which guarantees every later beat (pulls are consecutive). Effective lead from `w_next` to `wvalid` is `W_LEAD`+1 at least; the client sees the exact `W_LEAD` protocol | info |
| S9 | PRE protection rule | "no queued request wants the row it would close" | applied only while a burst streams (look-ahead); when idle the arbitrated target may close any row (otherwise a mutual block is possible). Aged rows are closed regardless | info |
| S10 | Same-row back to back vs weights | "same-row pieces of the same port are granted back to back unless another port waited > 60 us" | a priority below urgent and above WRR that does not consume WRR credit; a port streaming one row can therefore take many pieces in a row (seen in the tests) | info |
| S11 | Urgent bound formula | contract: about L_MAX + 27 = 155 | derived terms in the header of `tau_sdram_sched_v.sv`; with the defaults it also gives 155 (L_MAX 128 + PULL_AHEAD 4 + max(conflict 10 + turnaround 3, refresh 17) + RD_LAT 4 + 2). Measured maxima 119..137 cycles under random conflicting load, never above | info |
| S12 | Refresh policy | "one per idle gap, never while urgent waits" cannot hold under saturation | idle gap, or between grants from `REF_SOFT_DEBT` (4) when no urgent request waits, and at the next burst boundary from `REF_HARD_DEBT` (7) even while an urgent request waits (the PHY forces at 8 and flags a fault) | ask |
| S13 | Preempt acknowledge | offer NOP with `preempt_ack` | `preempt_ack` = preempt & no burst open; the scheduler lets the current piece finish (PHY timeout 136 > 128 + margin) | info |
| S14 | Chip-model storage | the model's direct-mapped hash collides for multi-bank contiguous data | added parameter `MEM_COMPACT` (default 0, original behaviour) to `sim/sdram_chip_model.sv`: an exact store for test addresses with row[12]=0, row[7:4]=0 | info |

## Not done / limits
* No replay, no area/Fmax probe, no Quartus; no Pocket. CL2 is the main target; CL3 runs a subset.
* Only one read (RD) chains across banks at the boundary by permit; chained-BL8 is not implemented (contract 9c).
* The urgent bound was measured with random arrivals, not an exhaustive phase sweep.
* Write pieces shorter than W_LEAD+1 words do not chain after a short piece (a few idle cycles).
