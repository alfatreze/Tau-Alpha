# WebAssembly modules of the meters (owner decision D-M15, 2026-11-07)

**The rule.** Every Player 2 meter has a WebAssembly module of the firmware's OWN drawing source, so the meter lab and Tau Omega draw what the Pocket draws, command for command, and nobody keeps a hand-written twin in step. A new meter ships with its module; `sim/test_meter_wasm_coverage.py` fails for a Player 2 meter (a manifest with a `p2` block) that has no `tools/meters/preview/meters/<key>_wasm.js`, except the meters listed in its `KNOWN_GAPS`, which is work to do and only shrinks.

**State (2026-11-07): all seven Player 2 meters have their module** (Layered Wave with a timed build, Sound Map, Waterfall Grid (B-983), Winamp Bars, Winamp Scope, Master VU and Chladni (B-984)). The hand-written JS twins of Winamp Bars, Winamp Scope and Master VU are deleted; Chladni, which never had a lab module, now has its preview. `KNOWN_GAPS` in the coverage test is empty.

**How a module is made.** `tools/meters/preview/wasm/<key>_wasm.c` includes the meter's source the way its pack builds it (`P2_PACK`), redirects the engine calls the meter makes (`gfx_rect`, `gfx_scroll_*`, `gfx_cblit`, ...) to imports, provides `th_role`, and exports the input structure, the spectrum, the live parameters and `tick_raw`. `tools/meters/preview/wasm/build_wasm.py <key>` (Homebrew llvm + lld) writes the committed `meters/<key>_wasm.js` with the SHA-256 of every file it was built from (and `params`, the parameter keys in the module's order, for the meters whose enum the script knows: `ENUMS`). `meters/<key>.js` is the adapter the lab and Tau Omega call (`state`, `tick(ctx)`, `ready()`); in node the compile is synchronous, in a browser asynchronous. Four adapters (Bars, Scope, VU, Chladni and every scaffolded meter) are made by the shared factory `meters/_wasm_meter.js` (one environment for every engine call; `inputs(ctx, x, vals)` sets a meter's extra input: the Scope's capture words, the VU's peaks). The hardware a meter reads through registers is modelled in its wrapper (the Scope's capture block, the CPU cycle counter). A meter made by `make new-meter` gets its wrapper and adapter written, and ALL modules rebuilt (the generated `meter_presets.h` grew and every module records its hash); `build_wasm.py` discovers a wrapper without an entry.

**Proof.** The native C of the same source and the module must issue the same engine commands for the same input trace: `sim/test_layered_wave_golden.py` (2.0 M commands), `sim/test_waterfall_golden.py` (83 scenarios, 535 k commands), `sim/test_meter_wasm_golden.py` (Bars, Scope, VU, Chladni and any scaffolded meter: 77 scenarios, 1.05 M commands: every factory preset, each parameter at its lowest and highest value, a pause, the degrade levels, a forced repaint, a moved box, the fullscreen box, the Scope with and without the blend) and `sim/test_sound_map_twin.py`.

**The lab's framebuffer** (`tools/meters/preview/tau_fb.js`) models the engine calls a module makes: `rect`, `bar`, `text`, `copy`, `blit`, `scrollLeft`, `scrollDown`, and for the Waterfall the off-screen **stash** (`rectStash`: raw values in a 512 x 1024 plane below and beside the visible frame), the palette (`clutLoad`) and the palette blit (`cblit`: stash indices through the palette into the drawing target), Chladni's mailbox, copy inside the engine memory, scaled blit and fence (`mbWrite`, `mbRead`, `blitAbs`, `sblit`, `fence`), and the Scope's pipelined blend (`blendOn`, `blendBlit`, `blendOff`). A new meter that uses another engine call needs it modelled there, with a log line the native harness prints the same way.
