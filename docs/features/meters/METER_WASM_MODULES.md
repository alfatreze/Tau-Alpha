# WebAssembly modules of the meters (owner decision D-M15, 2026-11-07)

**The rule.** Every Player 2 meter has a WebAssembly module of the firmware's OWN drawing source, so the meter lab and Tau Omega draw what the Pocket draws, command for command, and nobody keeps a hand-written twin in step. A new meter ships with its module; `sim/test_meter_wasm_coverage.py` fails for a Player 2 meter (a manifest with a `p2` block) that has no `tools/meters/preview/meters/<key>_wasm.js`, except the meters listed in its `KNOWN_GAPS`, which is work to do and only shrinks.

**State (2026-11-07).** Done: Layered Wave (`LAYERED_WAVE_WASM.md`, plus a timed build), Sound Map, **Waterfall Grid (B-983)**. Still to do: Winamp Bars, Winamp Scope, Master VU and Chladni (the first three have hand-written JS twins in the lab; Chladni has no lab module).

**How a module is made.** `tools/meters/preview/wasm/<key>_wasm.c` includes the meter's source the way its pack builds it (`P2_PACK`), redirects the engine calls the meter makes (`gfx_rect`, `gfx_scroll_*`, `gfx_cblit`, ...) to imports, provides `th_role`, and exports the input structure, the spectrum, the live parameters and `tick_raw`. `tools/meters/preview/wasm/build_wasm.py <key>` (Homebrew llvm + lld) writes the committed `meters/<key>_wasm.js` with the SHA-256 of every file it was built from (and `params`, the parameter keys in the module's order, for the meters whose enum the script knows: `ENUMS`). `meters/<key>.js` is the adapter the lab and Tau Omega call (`state`, `tick(ctx)`, `ready()`); in node the compile is synchronous, in a browser asynchronous.

**Proof.** The native C of the same source and the module must issue the same engine commands for the same input trace: `sim/test_layered_wave_golden.py` (2.0 M commands), `sim/test_waterfall_golden.py` (83 scenarios, 535 k commands: every factory preset, modes, flows, palettes, cell sizes, a pause, the degrade levels, a forced repaint, a moved box, the fullscreen box) and `sim/test_sound_map_twin.py`.

**The lab's framebuffer** (`tools/meters/preview/tau_fb.js`) models the engine calls a module makes: `rect`, `bar`, `text`, `copy`, `blit`, `scrollLeft`, `scrollDown`, and for the Waterfall the off-screen **stash** (`rectStash`: raw values in a 512 x 1024 plane below and beside the visible frame), the palette (`clutLoad`) and the palette blit (`cblit`: stash indices through the palette into the drawing target). A new meter that uses another engine call needs it modelled there, with a log line the native harness prints the same way.
