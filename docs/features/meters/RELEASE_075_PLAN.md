# Release 0.7.5: external meters, the meter menu, per-meter settings, the SDK (plan)

Status 2026-11-18: **plan, decided by the owner; nothing of workstreams W1 to W3 is built.** Decisions are in `docs/DECISIONS.md` D-M25. What is already done: the external-meters firmware (P0 to P2.5), the release plumbing (P2.6), the package tool, the golden vectors for Omega; **pending: the Pocket smoke test of the normal build (TAU DEV 225)**.

## 1. What the owner decided (2026-11-18)
1. **The release is 0.7.5** (not 0.8.0). It must have: the external meters, **the full meter SDK and its testing**, the meter menu change below, per-meter Configure, and **every meter keeping its own settings across a restart (a save file)**.
2. **Meter menu:** the METER list leaves Settings > Appearance and becomes its own entry in the main (Settings) menu, **directly below APPEARANCE**. The list opens with the **active meter pre-selected**. The "METER: CONFIGURE" row (configure the active meter) is **removed**; instead **every configurable meter row shows a small settings icon** and can be configured, not only the active one. The active meter is still configured on screen as it is now. **A sets the meter; a different key configures** (X, as the list's hint already says).
3. **Per-meter settings:** the owner chose "every meter keeps its settings (a save file)" over keeping 2 tuned meters or packing 3 or 4: the Pocket's **native save slot** (a `nonvolatile` data slot written to `Saves/` on Quit). This needs an FPGA change and a new bitstream.

## 2. My reading where the answers leave room (the owner may correct it)
- Configure of a meter that is **not** the set one: the page shows a live preview of that meter (its pack is loaded for the page) and **leaving it brings the set meter back**; only A changes the set meter. The settings edited there belong to that meter and are saved with the others.
- The Start+X shortcut (Configure of the active meter) stays; only the Appearance row goes.
- "Configurable" = the meter's descriptor has parameters (all seven shipped meters do).

## 3. Workstreams (W1 and W3 can start now, in parallel; W2 starts with a spike)
**W1 Menu and per-meter Configure (firmware, `fw2/ui`):** new METERS page below APPEARANCE (the P2.5 list moved, same order as X, active meter pre-selected); Appearance loses METER and METER: CONFIGURE; settings icon on configurable rows (not on greyed or hidden ones); X on any row opens that meter's Configure page (descriptor from its pack, live preview, parameters, presets); settings stored through ONE interface (`meter_settings_get/put(id_hash, ...)`) backed first by today's two-tuning pool, then by W2's save file; the user guide, test sheets and the About page follow. Pocket test: DEV 226 or the next number.
**W2 Per-meter save file (RTL + firmware + tools):** the long pole.
- **S0 research and design (host):** the Analogue references (data.json `nonvolatile`, the size table, KB-001/004/074/005/032/033, the NGPC unloader pattern) and what failed in September (issue 019: deferload slot with core-issued `0184`/`0188`, never the native route; the old boot hang and the size-table overwrite are fixed). Write the design: a small dual-clock BRAM at the slot's bridge address (flush reads at Quit, load writes at boot), the CPU side writing through on every edit, the size-table entry, the first-file problem (KB-074: the exit flush only writes a slot that was LOADED, so the installer or Omega pre-creates a zeroed file; the core must cope with a missing or zero file), parameters bit choices, file location `Saves/tau/<core>/`.
- **S1 hardware spike (the first fit):** a probe bitstream and a diagnostic firmware test: write a pattern, Quit, boot, read back; two seeds (about 1h45 each, say the finish time when launched). **Gate: it works on a Pocket before anything else is built on it.**
- **S2 format and firmware:** `tau-meter-settings.bin` v1 (records keyed by `id_hash`, `params_rev`, only the parameters that differ from the default, CRC, at most 8 KB for 64 meters), migration from the two-tuning pool, write-through on Configure edits, `persist_layout` unchanged or v3 (decide then), the commit rule unchanged.
- **S3 packaging and Omega:** `tau-compat.json` (the save slot as a user-data entry, the new bitstream `CORE_VERSION`), the installer creates the zeroed file, the golden vectors for Omega (a message first), the plugin's Check.
- **Facts so far:** the release fit has **274 of 308 M10K blocks used (34 free, about 42 KB)** and 84 % of the ALMs: a 4 to 8 KB buffer fits. **Risks:** a native route never proven on Tau; a new bitstream in the release (CORE_VERSION, Omega, the ROM pairing); timing closure on two seeds; hardware debugging time. **If S1 fails, stop and report: the fallback is the two-tuning pool (as built) and the owner decides.**
**W3 SDK and testing (tools, docs, repositories):** the SDK repository `tau-alpha-meter-sdk` (the template is its `template/` folder; owner decision 2026-11-18: one repository) and the collection `tau-alpha-meters`, MIT; creating public repositories needs the owner's approval); a documented, installable **toolchain recipe** (our own `toolchain/` is 1.6 GB and not shippable: pick what a developer can install and pin it); the **conformance suite** (a host runner over a `.tmeter`: manifest and package rules, ABI, window and pstate bounds, only host-table calls, draw-command and cycle budgets, determinism, a hang run against the watchdog model, a preview image); the document set (getting started, the ABI and host table, descriptors, parameters and presets, packaging, testing, publishing, the trust model of D-M23); the WebAssembly lab for authors; a **cold-start review** (a reviewer builds a meter from nothing); CI for the template. Not in this release unless the owner asks: the public catalogue with signed index and submissions (D-M23 verified tier).

## 4. Gates for 0.7.5
All of W1 to W3 done and tested; the normal build (`DIAG=0`) Pocket-tested for every user-visible feature (DEV 225 is the first); W2's S1 spike and the final save-file test on a Pocket; a release rehearsal build (`tools/make_release.py --player2`, nothing published) with the new bitstream; the Omega messages sent and its read side checked against the vectors; `params_rev` values decided; the persist registry's `since` entries (now `v0.8.0`) changed to `v0.7.5`; version, README and CHANGELOG bumped by the owner's go; the release assets compared with `SHA256SUMS.txt` (rule 8).
